# Building blocks of tidytargets

tidytargets is a tidy, pipe-friendly grammar for
[targets](https://docs.ropensci.org/targets/).

[`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md)
constructs a `tidytargets` object. Each method is a [target
factory](https://books.ropensci.org/targets/static.html#target-factories):
it appends `tar_target` definitions to a pipeline script. You compose
the pipeline with `|>`; [targets](https://docs.ropensci.org/targets/)
runs the dependency graph.

The composition is **lazy**.
[`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md),
[`tt_data()`](https://stemangiola.github.io/tidytargets/reference/tt_data.md),
[`tt_data_list()`](https://stemangiola.github.io/tidytargets/reference/tt_data_list.md),
[`tt_single()`](https://stemangiola.github.io/tidytargets/reference/tt_single.md),
[`tt_iterate()`](https://stemangiola.github.io/tidytargets/reference/tt_iterate.md),
[`tt_split()`](https://stemangiola.github.io/tidytargets/reference/tt_split.md),
[`tt_merge()`](https://stemangiola.github.io/tidytargets/reference/tt_merge.md),
and
[`tt_report()`](https://stemangiola.github.io/tidytargets/reference/tt_report.md)
only write factories into `{store}.R`. User functions are not called
until
[`tt_evaluate()`](https://stemangiola.github.io/tidytargets/reference/tt_evaluate.md)
(or evaluating the object; e.g., printing it in the console), which
closes the script and runs
[`targets::tar_make()`](https://docs.ropensci.org/targets/reference/tar_make.html).
Assigning the object does not print it, so an interactive session then
says the pipeline is ready to be evaluated, rather than appearing to do
nothing.

Pipelines are **incremental**. Add a step, change a parameter, or grow
the input list and [targets](https://docs.ropensci.org/targets/) skips
up-to-date targets, re-running only what the new graph requires. That is
why this vignette can show the script after each building block without
executing the pipeline.

This vignette walks through every building block and prints the targets
script after each step with
[`show_targets_script()`](https://stemangiola.github.io/tidytargets/reference/show_targets_script.md).

## Building blocks

### Workflow

| Function | Role |
|----|----|
| [`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md) | Start a pipeline: write the script header, optional mapped inputs |
| [`tt_evaluate()`](https://stemangiola.github.io/tidytargets/reference/tt_evaluate.md) | Close the script and run `tar_make()` |
| [`tt_read()`](https://stemangiola.github.io/tidytargets/reference/tt_read.md) | Read the full stored value of a named target |

### Data

| Function | Role |
|----|----|
| [`tt_data()`](https://stemangiola.github.io/tidytargets/reference/tt_data.md) | Snapshot a session object onto the store as one target |
| [`tt_data_list()`](https://stemangiola.github.io/tidytargets/reference/tt_data_list.md) | Snapshot a list onto the store as mapped units |
| [`tt_merge()`](https://stemangiola.github.io/tidytargets/reference/tt_merge.md) | Combine iterated results into one object |
| [`tt_split()`](https://stemangiola.github.io/tidytargets/reference/tt_split.md) | Turn a pipeline list into mapped units |

### Commands

| Function | Role |
|----|----|
| [`tt_iterate()`](https://stemangiola.github.io/tidytargets/reference/tt_iterate.md) | Map a function over inputs |
| [`tt_single()`](https://stemangiola.github.io/tidytargets/reference/tt_single.md) | Add one non-iterated target |

[`tt_factory()`](https://stemangiola.github.io/tidytargets/reference/tt_factory.md)
is internal and used by the command functions above.
[`tt_single()`](https://stemangiola.github.io/tidytargets/reference/tt_single.md),
[`tt_iterate()`](https://stemangiola.github.io/tidytargets/reference/tt_iterate.md),
[`tt_split()`](https://stemangiola.github.io/tidytargets/reference/tt_split.md),
and
[`tt_merge()`](https://stemangiola.github.io/tidytargets/reference/tt_merge.md)
all append
`target_list <- target_list |> target_append(tt_factory(...))` to the
script.

### Reporting and debug

| Function | Role |
|----|----|
| [`tt_report()`](https://stemangiola.github.io/tidytargets/reference/tt_report.md) | Render a Quarto / R Markdown report |
| [`tt_explore()`](https://stemangiola.github.io/tidytargets/reference/tt_explore.md) | Return one stored instance of a named target |
| [`tt_metadata()`](https://stemangiola.github.io/tidytargets/reference/tt_metadata.md) | Get or set free-form metadata on the pipeline object |

## Toy inputs

[`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md)
can be called with no inputs (script header and store only). A named
list of in-memory objects, one element per unit of iteration
(e.g. sample), registers mapped targets.
[`tt_data()`](https://stemangiola.github.io/tidytargets/reference/tt_data.md)
adds a session object later without splitting it;
[`tt_data_list()`](https://stemangiola.github.io/tidytargets/reference/tt_data_list.md)
adds a list as mapped units.

`inputs`` ``<-`` `[`list`](https://rdrr.io/r/base/list.html)`(`` `` sample_a ``=`` ``1``:``3``,`` `` sample_b ``=`` ``4``:``6`` ``)`

## `tt_initialise()`

This writes `{store}.R` and saves configuration. If you passed mapped
inputs, it also registers:

- `input_list` — the named input vector or list (override with
  `target_output`)
- `sample_names` — the names of that vector or list

With no `computing_resources`, the pipeline is sequential. With no
`store`, a unique `./tidytargets-<HASH>` directory is created. With no
inputs, start from
[`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md)
and add objects with
[`tt_data()`](https://stemangiola.github.io/tidytargets/reference/tt_data.md).

Packages currently attached in your session
([`.packages()`](https://rdrr.io/r/base/zpackages.html)) are recorded at
[`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md)
as names on `tar_option_set(packages = )` so workers can
[`library()`](https://rdrr.io/r/base/library.html) them.
[`tt_initialise()`](https://stemangiola.github.io/tidytargets/reference/tt_initialise.md)
messages that list so you can check the same packages are available on
HPC. Objects in the global environment are not copied; bring those in
with
[`tt_data()`](https://stemangiola.github.io/tidytargets/reference/tt_data.md)
or `user_function_source_path`. Pass `packages` to override the
snapshot. Attach libraries before initialise (or pass `packages`) if a
later command needs them.

[`tt_single()`](https://stemangiola.github.io/tidytargets/reference/tt_single.md),

[`tt_merge()`](https://stemangiola.github.io/tidytargets/reference/tt_merge.md)
accept `user_function_source_path`. The path is written as `source(...)`
in the targets script so workers can load helpers that are not in a
package.
